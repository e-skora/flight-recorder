## Accepted Constraints Carried Forward (no `DECISIONS.md` entry; they enforce existing truth)

- Schema v1 keeps the closed seven-key typed evidence vocabulary through the MVP.
- `persona.selected` renders with kind label `EVENT`.
- A decision's `decision_boundary` is the decision event's occurrence instant; escalate before ever letting them differ.
- Counterfactual replay is Phase 3 (3A engine merged; 3B browser experience next), per D-011.
- `evaluator-v1` temporal semantics (accepted by review 2026-09-06, reaffirmed 2026-09-07): "observed within N days before the decision boundary" reads the linked evidence version's `observed_at` as that calendar date at `00:00:00Z` and matches when it is not after `T(d)` and the elapsed time `T(d) − o` is at most `N × 24` hours (inclusive); future observations excluded; `PRODUCT.md` leaves this precision open, so it is evaluator-v1 semantics, not product truth, and Phase 3 replay under `v5.1` inherits it.
- Rule grammar is closed: a factor `rule` is exactly one of the four shapes present in the canonical artifacts, matched in full (`fullmatch`); anything else, including a trailing newline, is an explicit `UnsupportedRule`. `missing_value_behavior` other than `no_match_contributes_zero` is refused. Boolean values fit no rule shape.
- Reconstruction semantics: `consumed` = available and referenced by a factor whether or not the rule matched; comparison with the record is set equality of (`input_key`, `evidence_version_id`, `contribution`) over consumed factors; divergence raises `ReconstructionMismatch`, never a best-effort result; `evidence_versions` is read only by the preserved id.
- Reconstruction verifies, at the context read and before any evaluation, that every preserved evidence reference (consumed or ignored) has `available_at` not after the decision's stored boundary, as a string comparison on the collector's fixed-width normalized timestamp form (`YYYY-MM-DDTHH:MM:SS.ffffffZ`, lexical order is chronological; the argument is the stored boundary text, never an arbitrary ISO string); a later reference is `IntegrityFailure("available_at")`; equality admitted; the sealed context is verified, never rebuilt from timestamps, and the supersession link is never followed. This verifies sealed-context membership; it does not guarantee detection of arbitrary database corruption (accepted by review 2026-09-08).
- A counterfactual is `R(Lc, H(d))` computed on demand by `replay(conn, decision_event_id, current_artifact_hash)` and never persisted (D-011); it is a `Counterfactual`, a type unrelated to `Reconstruction`, carrying the fixed, validated label `counterfactual`; the current artifact is verified by `verify_artifact_row` (hash, schema, row identity, evaluator identity; the decision-identity check alone is skipped) and must share the decision's class; `H(d)` is read through `load_context` with the stored boundary text, so every preserved reference is availability-verified exactly as for the original; an original that cannot be reproduced exactly yields no counterfactual; `compare` classifies each key as added / removed / unchanged / reweighted / changed by factor presence, rule text, weight, input state, match, and contribution, reports `unavailable` and `absent` missing inputs separately, and satisfies `score_delta == sum(contribution_delta)`. Engine-level only: UI rendering of these states (3B) and analytics exclusion of counterfactuals (Phase 5) remain open (accepted by review 2026-09-08).
